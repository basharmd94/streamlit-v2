WhatsFly Integration Guide

A working reference for connecting your Streamlit analytics to WhatsApp — sending customers targeted product offers and excess-stock deals, and keeping sales reps aligned on what to focus on. Written to hand to Claude Code as build context.

Overview

WhatsFly is a WhatsApp Business Solution Provider — it sits on top of Meta's official WhatsApp Cloud API and adds messaging, contact management, and campaign tools behind a single HTTP API. For your use case, it's the delivery layer: your Streamlit app already knows who is interested in what, and which stock needs to move. WhatsFly is how that knowledge turns into a WhatsApp message in a customer's hand, or a briefing in a rep's.

Two things it's doing for you specifically:

  • Customer offers — turning your interest scores and excess-stock lists into personalized, priced WhatsApp messages, sent through pre-approved templates.
  • Rep coordination — pushing a rep's product focus list straight to their WhatsApp, and routing customer replies to the right person inside WhatsFly's team inbox.

How it fits your workflow

The pipeline has one input (your Streamlit analysis) and one feedback loop (replies and delivery status flowing back in). Everything in the middle is what Claude Code will build.

The webhook receiver is the one piece that can't live inside Streamlit itself — it needs a small always-on endpoint (FastAPI/Flask works fine) since Streamlit doesn't accept inbound HTTP calls. More on that in Webhooks.

Core concepts

Authentication

Every call carries an apiToken — a single key tied to your WhatsFly account, found in your dashboard. Treat it like a password: it authenticates every read and write across your whole account, not just WhatsApp.

phone_number_id

This identifies which connected WhatsApp Business number a call applies to. If you only run one number, it's a constant you'll pass on nearly every request. If you later connect a second number, it's how you tell WhatsFly which one to use.

Session messages vs. template messages

This is the single most important rule for your campaign use case. WhatsApp splits outbound messages into two kinds:

TypeWhen you can send itEndpoint
Session (text/file/buttons)Only within 24 hours of the customer's last message to you/whatsapp/send, /whatsapp/send/file, /whatsapp/send/interactive-buttons
TemplateAny time — this is how you reach someone who hasn't messaged you recentlygenerated per-template in the dashboard

Your product-offer and excess-stock campaigns are, almost by definition, outbound-first — you're reaching customers who haven't just messaged you. That means they need to go out as template messages, pre-approved by Meta. See Creating & approving templates.

Subscribers

A subscriber is a WhatsApp contact under one of your phone numbers. This is where you'll attach the output of your Streamlit analysis — recommended product, offer price, interest score — using custom fields, and use labels for quick segmentation (e.g. a label per campaign, per product category, or per rep).

Response shape — one inconsistency to code around

Heads up: most endpoints return "status":"1" or "status":"0" as a string. The catalog endpoints (/catalog/list, /catalog/order/status-change) return "status":true/false as a real boolean. Have your pipeline check for both forms rather than assuming one.

Creating & approving templates

The endpoint list you shared doesn't include a "create template" call — only a get for existing ones (see Templates & bot flows), and a UI-driven template picker for sending. That's consistent with how WhatsApp templates generally work: you build and submit them once through a dashboard, and once approved, you send against them programmatically. Here's the process:

  1. Open the template builder in your WhatsFly dashboard Not part of the HTTP API — this step happens in the app.whatsfly.net UI.
  2. Choose a category Marketing (promotions, offers — what you'll use for stock clearance and product recommendations), Utility (order/account updates), or Authentication (OTPs). Category affects both Meta's review and per-message cost.
  3. Write the body with variables Use {{1}}, {{2}}, etc. as placeholders you'll fill per-customer at send time — name, product, price. Add an optional header (text/image) and footer.
  4. Submit for review Meta reviews the template — typically minutes to 48 hours. Marketing templates get more scrutiny than Utility ones; avoid vague, ad-like phrasing with no concrete value, since that's the most common rejection reason.
  5. Check status via the API The Bot Template endpoint returns a status field — Approved, Rejected, or Pending — for each template, so your pipeline can confirm a template is live before using it in a campaign.

An example body for your excess-stock use case:

Category: Marketing
Name: excess_stock_offer_v1
Body: Hi {{1}}, we noticed you were interested in {{2}}.
We've got it in stock now at a limited-time price of {{3}} —
only while supplies last!
Footer: Reply STOP to opt out

Worth deciding now: a small library of reusable templates — one for "back in stock," one for "price drop on something you viewed," one for "excess stock clearance" — each with 2–3 variable slots (name, product, price). Build and get these approved before Claude Code wires up the sending pipeline, since template turnaround is the slowest step in the whole loop.

API reference

Base URL: https://app.whatsfly.net/api/v1 — every endpoint below is relative to this. Most accept GET or POST; POST is shown as the primary form since apiToken shouldn't sit in a URL that ends up in logs or browser history.

Messaging & media

POST/whatsapp/send

Send text message

Free-form session message. Only works within 24 hours of the customer's last message — see Core concepts.

  • apiTokenrequired
  • phone_number_idrequired
  • phone_numberrequired — country code, digits only
  • messagerequired — text content
POST(dashboard-generated per template)

Send template message

The endpoint you were shown is generated per-template from a picker in the dashboard rather than documented as a fixed path/param set. Pick the WhatsApp account and template there to get the exact call, or ask WhatsFly support for the generic template-send contract — this is the one you'll lean on most for campaigns, so it's worth confirming precisely before Claude Code builds against it.

POST/whatsapp/send/interactive-buttons

Send interactive buttons

A session message with up to 3 reply buttons (max 20 characters each). Can carry an image/video/document header.

  • apiToken, phone_number_id, phone_number, messagerequired
  • buttonsrequired — JSON array, 1–3 items, each {id, title}
  • button_header_text / button_footer_textoptional
  • media_url / media_idoptional — one or the other, for a media header
  • media_typerequired if media_id or extension-less media_url used
POST/whatsapp/send/file

Send file / media

Sends an image, video, audio, or document as its own message.

  • apiToken, phone_number_id, phone_numberrequired
  • media_urlrequired if no media_id
  • media_idrequired if no media_url
  • media_typerequired with media_id, or extension-less URL
  • media_namerequired when media_type is document
  • media_caption_textoptional
POST/whatsapp/upload/media

Upload media

Multipart upload to get a media_id for reuse in Send File — useful if you're sending the same product image to many customers.

  • apiToken, phone_number_idrequired
  • media_filerequired — multipart field, must be named exactly media_file

Conversations & status

GET/POST/whatsapp/get/conversation

Get conversation

Fetches message history with one subscriber — useful for surfacing recent context before a rep follows up.

  • apiToken, phone_number_id, phone_number, limitrequired — limit up to 50
  • offsetoptional — page number, default 1
GET/POST/whatsapp/get/message-status

Delivery/read status

Poll the status of a specific sent message — sent, delivered, read, or failed. For campaigns at any scale, prefer the webhook (see Webhooks) over polling this per message.

  • apiToken, wa_message_id, whatsapp_bot_idrequired
GET/POST/whatsapp/get/post-back-list

Post-back list

Configured postback actions (what happens when someone taps a button or quick reply) for a number.

  • apiToken, phone_number_idrequired

Two use-case walkthroughs

A. Excess-stock / product-interest offer campaign

  1. Score and selectYour Streamlit analysis produces a list: customer phone, recommended product, offer price, interest score.
  2. Ensure the subscriber existsFor each customer, call Get Subscriber; if missing, Create Subscriber.
  3. Attach the analysisAssign Custom Fields with recommended_product, offer_price, interest_score.
  4. Tag the batchCreate (or reuse) a label like excess-stock-sep-2026 and assign it — this becomes your reporting key later.
  5. Send the templateFire the approved offer template per customer, filling {{1}}/{{2}}/{{3}} with name, product, price.
  6. Track outcomesDelivery/read status and any reply arrive via webhook; log them back against the label for a campaign report in Streamlit.

B. Sales rep coordination

  1. Rank priorities per repStreamlit's rep-performance analysis outputs which products each rep should push this week.
  2. Send the briefingSend Text (if the rep messaged your bot recently) or a Utility-category template to each rep's WhatsApp with their focus list.
  3. Route customer repliesWhen a tagged customer responds, use Assign Chat to Team Member so it lands with the right rep in WhatsFly's team inbox.
  4. Keep a shared recordAdd Notes on the subscriber so context (which offer was sent, at what price) travels with the conversation even if a different rep picks it up.

Webhooks

A webhook is WhatsFly calling you — a POST to a URL you register, fired the instant a customer replies, a message status changes, or someone taps a template button. It's how step 6 in the workflow diagram gets fed.

  • Register the URL in the WhatsFly dashboard's webhook/integration settings.
  • Streamlit can't receive these directly — it isn't built to host a persistent inbound endpoint. Plan on a small separate service (FastAPI or Flask is plenty) that receives the POST, writes it to a database, and responds 200 OK quickly.
  • Streamlit then reads from that same database to show live replies, delivery rates, and campaign results.
  • Button taps on your interactive messages map back to the id you set when sending — cross-reference against Post Back List if you're using postback-configured buttons rather than one-off ones.

Gotchas & security notes

  • Use POST, not GET, wherever both are offered. GET puts apiToken directly in the URL, which tends to end up in server logs, browser history, and proxy caches.
  • Store the token outside your code. Environment variable or secrets manager — never hard-coded, never committed.
  • Phone numbers are country code + digits only, no + sign, no spaces.
  • Response envelopes aren't fully consistent — see the callout in Core concepts. Check for both string and boolean status.
  • Message credits are capped per plan tier — a bulk campaign against a large list could hit that ceiling mid-run. Confirm your plan's monthly limit before sizing a campaign.
  • The 24-hour rule is the one that will silently break things — a session-type send to a customer who hasn't messaged in over a day will simply fail. Anything cold-outbound needs a template.

Before you build

Handy as a literal checklist to work through before handing this to Claude Code for pipeline development.

  • Confirm your phone_number_id(s)From the dashboard, for each connected WhatsApp Business number you'll send from.
  • Get the exact template-send request contractThe endpoint is UI-generated per template — pull one real example from the dashboard before coding against it.
  • Design your custom-field schemaDecide field names for interest score, recommended product, offer price — and create them once in the dashboard.
  • Get at least one Marketing template approvedSubmit the excess-stock offer template early — Meta review time is the slowest step in the whole pipeline.
  • Pick a labeling conventionSomething like {campaign-type}-{month}-{year} keeps reporting straightforward later.
  • Stand up the webhook receiverA small FastAPI/Flask service, separate from Streamlit, to capture replies and delivery status.
  • Check your plan's message-credit limitMake sure it covers your first campaign's send volume.
